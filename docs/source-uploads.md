# Deploy uploaded source

In an Application's **Source** tab choose **Upload source archive**. Select a ZIP, tar or tar.gz file, its build context (relative to the archive root), and Dockerfile path (relative to that context). Upload and review the included/excluded paths, then select **Use this revision**. Deploy builds a new immutable image through the same queue, readiness checks and activation flow as GitHub builds. A failed build leaves the active deployment running. Deployment History records the uploader/deploy initiator, source SHA-256, build output and final image identity. Rollback uses the original local image, without rebuilding the archive.

Each upload is limited to 32 MiB compressed, 128 MiB expanded, 20,000 entries and 64 path components. Absolute/parent paths, duplicate paths, symlinks, hardlinks, devices, encrypted ZIP entries and unsupported archive entries are rejected. Archive paths must be UTF-8. Dockerfile-specific `<Dockerfile>.dockerignore` takes precedence over `.dockerignore`. Preview lists are capped at 200 paths each; the displayed count covers the full filtered context.

Uploads contain **code only**. They never import SQL dumps or overwrite runtime volumes, and runtime environment variables are not injected as build arguments. Review and exclude `.env`, credentials, database dumps, `.git`, dependencies and persistent-data directories before uploading. Include an appropriate `.dockerignore`; Ferrix does not infer which source files your Dockerfile requires.

Revisions are private to their Application and organization/project. Browser managers or appropriately scoped API keys can upload/select revisions. There is no public archive download endpoint. The latest five revisions, currently selected revision and revisions used by queued/running builds are retained; older unselected revisions are pruned on subsequent uploads. Archive pruning does not remove Docker images or deployment checksums. Back up the Ferrix database privately: it contains uploaded source archives. Use encrypted disks/database backups for source confidentiality at rest. Deleting an Application removes its stored uploads through database foreign keys.

API: `POST /api/v1/services/{id}/source/upload?context=.&dockerfile=Dockerfile` with an `application/octet-stream` archive body returns `upload_id`, `sha256`, and `preview`. Review it, then `POST /api/v1/services/{id}/source` with `{"mode":"upload","upload_id":"…"}`. Deploy separately with the existing deploy endpoint. API keys require `manage` for upload/source edits, `secrets:read` for source settings and `deploy` for deployment. Keys never exceed their user's organization permissions or project scope.
